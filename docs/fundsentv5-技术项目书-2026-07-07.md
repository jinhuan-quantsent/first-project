## 一、项目核心定位与整体逻辑闭环

### 1.1 核心定位

面向专业投资者的极简基金情绪分析工具。

**一句话核心逻辑**：  
全市场杂乱数据 → 15因子 Sigmoid非线性聚合 → 一个情绪分(0-100) + 七级信号 + 四星置信度 + 仓位调整建议 + 趋势卫士行为引导

### 1.2 完整数据流转链路

```
Tushare Pro / 东方财富 / 腾讯财经 / AKShare（三级降级）
       ↓
15因子原始值获取（factor_engine/ 每个因子一个类，含DIVERGENCE背离因子）
       ↓
层1：分位数标准化（quantile.py，5年窗口=1260天）
       ↓
层2：Sigmoid映射（sigmoid.py，因子特异c/k参数）
       ↓
层3：分歧度动态加权（aggregator_v5.py，factor_std → penalty）
       ↓
综合情绪分 composite_score (0-100)
       ↓
七级信号映射 + 防跳变（signal_mapper.py）
       ↓
置信度5维度评分 + 四道假信号防线（confidence.py）
       ↓
5×7仓位调整矩阵 + 四层修正（position_v5.py）
       ↓
趋势卫士（MA20 + MACD双指标）→ 两套独立闸门体系（持仓风控+建仓准入）
       ↓
板块情绪系统（5因子×31板块 + 双轨制过滤器 + 建仓评级4档 + 三级降级架构）
       ↓
置信度双路径V5.2（板块基金→板块缓存 / 宽基基金→沪深300）
       ↓
仓位引擎V5.1（总资产分母 + 组合约束 + 冷却期差异化 + 金额字段）
       ↓
每日决策快照（28字段 → daily_signal_snapshot表 → CSV下载）
       ↓
盘中预演模块（实时估值 gszzl × 弹性系数 → 预演分数 + 操作建议 + Gate区间 + 对账校准）
       ↓
策略验证分析模块（14:45系统建议持久化 → 14:47 DeepSeek AI建议(independent模式) → 17:35 T+1回验）
       ↓
MACD双系统（SentimentMACD 5/20/9 + PriceMACD 12/26/9 → 背离检测 → DIVERGENCE因子）
       ↓
系统进化4方向（滚动窗口 + Per-fund成绩单 + 因子相关性 + 数据完整性 → analysis_daily_snapshot表）
       ↓
IMA知识库自动上传（每日策略验证表+分析快照表 → CSV → IMA KB）
       ↓
缓存自动刷新（Redis版本号 → 前端60s轮询 → 6个调度器插入点 → 模块缓存失效）
       ↓
API 输出 → 前端 React 展示（含AI分析面板+MiniMacdChart双线+DivergenceBadge+自动刷新）
```

### 2.3 数据源三级降级架构

```
请求数据 → Tushare Pro（主数据源，2000+积分）→ 成功 → 返回真实数据
           ↓ 失败/限流
           东方财富/腾讯财经 API（备用数据源）→ 成功 → 返回真实数据
           ↓ 失败
           AKShare（降级）→ 成功 → 返回真实数据
           ↓ 失败
           Mock 数据（兜底）→ 返回估算数据 + 标记 _data_source: "mock"
```

**注意事项**：
- 东方财富 push2.eastmoney.com 从阿里云 ECS 访问被拒（IP 封锁），重仓股实时行情改用腾讯财经 API（qt.gtimg.cn）
- Tushare moneyflow_hsgt 限流 1次/分钟，需配合缓存使用

### 2.4 核心模块输入/输出/职责

| 模块 | 输入 | 输出 | 职责 | 联动 |
|------|------|------|------|------|
| factor_engine（14个因子类） | index_code, trade_date | FactorRawValue（raw_value） | 获取因子原始值 | → quantile.py |
| quantile.py（层1） | FactorRawValue | FactorQuantileResult（percentile） | 分位数标准化(5年窗口) | ← factor_history表 |
| sigmoid.py（层2） | FactorQuantileResult | FactorSigmoidResult（sigmoid_score） | Sigmoid映射(因子特异c/k) | → aggregator_v5.py |
| aggregator_v5.py（层3） | List[FactorSigmoidResult] | CompositeScore（score） | 分歧度动态加权 | → signal_mapper.py |
| signal_mapper.py | CompositeScore.score | signal_level（S+/S/A/B/C/D/E） | 7级信号映射+防跳变 | → confidence.py |
| confidence.py | sigmoid_results + signal_level | confidence_stars（1-4） | 5维度评分+四道防线 | → position_v5.py |
| position_v5.py | signal_level + confidence_stars + current_pct | PositionAdvice（action + target_pct） | 5×7矩阵+四层修正 | ← trend_guard.py |
| trend_guard.py | nav_history + signal_level | TrendGuardResult（gate_triggered + admission_gate + trend_signal） | MA20+MACD判定+两套独立闸门 | → position_v5.py |
| sector_scorer.py | 板块行情原始数据 | 板块情绪评分+signal_level | 5因子加权+建仓过滤器 | → 机会雷达 |
| sentiment_macd.py | composite_score序列 | MACD线+信号线+柱状图 | 情绪分MACD指标 | → confidence.py（持续性评分） |
| divergence_detector.py | price_series + sentiment_series | divergence_type + strength | 顶底背离检测 | → confidence.py（防线3） |
| data_fetcher.py | fund_code / index_code | nav_history / index_data | 统一数据获取（含降级） | ← 所有引擎模块 |
| factor_history.py | index_code + factor_name | 历史序列（1260天） | 因子历史存储与查询 | ← quantile.py |
| eastmoney.py (get_fund_realtime_nav) | fund_code | gszzl(实时估值涨幅) + nav | 双路冗余估值（fundgz主+FundMNFInfo备） | ← scheduler预演 |

### 4.2 三层计算链路

#### 层1：分位数标准化（quantile.py）

**原理**：不再问"波动率15%应该是多少分"，而是问"波动率15%在过去5年中处于什么位置"

- 滚动窗口：`1260` 天（5年 × 252交易日）
- 最小样本数：`252` 天（1年），不足时 `percentile` 返回 `None`，降级为 `0.50`
- 计算公式：`percentile = stats.percentileofscore(historical_values, raw_value, kind="rank") / 100.0`
- 使用的历史数据来源：`factor_history` 表（需先回填）

**降级策略**：数据不足时 `percentile = 0.50`（中位数，偏中性）

#### 层2：Sigmoid非线性映射（sigmoid.py）

**公式**：
```
sigmoid_score = 100 / (1 + exp(-k × (percentile - c)))
```

- `c` 控制中点位置（c=0.5 表示中位数50分对应Sigmoid中点）
- `k` 控制敏感度（k越大，曲线越陡，中间区域敏感度越高）
- 输入：`percentile ∈ [0, 1]`
- 输出：`sigmoid_score ∈ [0, 100]`

**反向因子处理**（direction=fear 的因子）：
```python
if factor_name in REVERSE_FACTORS:
    sigmoid_score = 100.0 - sigmoid_score
```

**各因子 Sigmoid 参数详解**：

| 因子 | c | k | 说明 |
|------|---|---|------|
| VOL | 0.50 | 3.0 | 中位数中点，中等敏感度 |
| ADR | 0.50 | 2.5 | 中位数中点，稍低敏感度 |
| ERP | 0.50 | 4.0 | 中位数中点，高敏感度（ERP变化影响大） |
| FLOW | 0.50 | 2.0 | 中位数中点，低敏感度 |
| ETF | 0.50 | 2.0 | 同上 |
| NHNL | 0.60 | 2.5 | 中点偏右（0.6），偏高时更易触发高分 |
| TURN | 0.40 | 3.0 | 中点偏左（0.4），偏低时更易触发低分 |
| POS | 0.50 | 1.8 | 低敏感度（仓位变化缓慢） |
| NBF | 0.50 | 2.5 | 同ADR |
| PCR | 0.30 | 4.0 | 中点偏左（0.3），PCR偏低时（避险情绪低）快速映射到高分 |
| NEWF | 0.50 | 2.0 | 同FLOW |
| MARGIN | 0.50 | 2.0 | 同FLOW |
| RSI | 0.50 | 2.5 | 同ADR |
| INDUSTRY_DIVERGENCE | 0.50 | 2.0 | 同FLOW |

#### 层3：分歧度动态加权（aggregator_v5.py）

**原理**：15因子得分分歧大时，综合分向50（中性）回归

**计算步骤**：
1. 计算15因子Sigmoid得分的标准差 `factor_std`
2. 计算惩罚系数 `penalty`：
   - `penalty = penalty_max - (factor_std / std_threshold) × (penalty_max - penalty_min)`
   - `penalty ∈ [0.5, 1.0]`
   - `penalty = 1.0` 时：无分歧，不惩罚
   - `penalty = 0.5` 时：极端分歧，最终得分向50回归50%
3. 应用惩罚：`final_score = weighted_sum × penalty + 50.0 × (1.0 - penalty)`

**配置参数**（在 `config.py` 中）：
- `V5_DIVERGENCE_PENALTY_MIN = 0.5`（最大分歧时的惩罚系数）
- `V5_DIVERGENCE_PENALTY_MAX = 1.0`（无分歧时的惩罚系数）
- `V5_DIVERGENCE_STD_THRESHOLD = 15.0`（Sigmoid得分0-100范围的合理阈值）

**市场体制判定**（aggrefator_v5.py 中 `calc_regime` 函数）：

| 体制 | 条件 | 说明 |
|------|------|------|
| `bull` | factor_mean > 60 | 牛市：因子得分均值 > 60 |
| `bear` | factor_mean < 40 | 熊市：因子得分均值 < 40 |
| `sideways` | 40 ≤ factor_mean ≤ 60 | 震荡市 |
| `extreme_volatility` | factor_std > 15.0 | 极端波动：因子得分标准差过大 |

#### 防跳变规则

**目标**：避免单日情绪分大幅跳跃导致信号等级剧烈变化，误导操作。

**规则**：
1. 单日分差 < 10分 → 最多变1级
2. 单日分差 ≥ 10分 → 最多变2级
3. 连续3天同向 → 额外允许1级

**实现逻辑**（signal_mapper.py `_anti_jump_check`）：
```python
max_diff = 1 if score_diff < 10 else 2
if consecutive_same >= 3:
    max_diff += 1

if abs(new_idx - prev_idx) > max_diff:
    # 限制跳变幅度
    direction = 1 if new_idx > prev_idx else -1
    limited_idx = prev_idx + direction * max_diff
    return LEVELS[limited_idx], True  # True = 跳变被拦截
```

```
半仓 (50%)     |  70%        |  60%        |  50%        |  50%        |  40%        |  30%        |  20%
```

**矩阵查表逻辑**（position_v5.py）：

```python
# 1. 当前仓位百分比 → 仓位等级

# 2. 信号等级 → 信号索引

# 3. 查表获取目标仓位百分比
current_idx = LEVELS.index(current_level)

```

### 5.2 四层修正逻辑

**修正顺序**（按优先级，在 `position_v5.py` 的 `calculate` 方法中）：

#### 修正1：置信度修正

**规则**：置信度星级 → 修正系数 `adj_factor`

| 置信度星级 | adj_factor | 说明 |
|------------|------------|------|
| ⭐️⭐️⭐️⭐️（4星） | 1.0（100%） | 完全采纳矩阵建议 |
| ⭐️⭐️⭐️（3星） | 0.75（75%） | 部分采纳 |
| ⭐️⭐️（2星） | 0.5（50%） | 谨慎采纳 |
| ⭐️（1星） | 0.0（0%） | 不操作（直接返回hold） |

**计算公式**：
```python
if target_pct > current_pct:
    # 加仓：置信度修正
    adjusted_pct = current_pct + (target_pct - current_pct) * adj_factor
elif target_pct < current_pct:
    # 减仓：置信度修正
    adjusted_pct = current_pct - (current_pct - target_pct) * adj_factor
```

#### 修正2：市场体制修正

**规则**：根据 `regime`（bull/bear/sideways/extreme_volatility）调整

| 体制 | regime_adj | 说明 |
|------|-----------|------|
| bull（牛市） | 1.1 | 市场过热，稍微降低目标仓位（防守） |
| bear（熊市） | 0.85 | 市场低估，稍微提高目标仓位（抄底） |
| sideways（震荡） | 1.0 | 不调整 |
| extreme_volatility（极端波动） | 0.7 | 大幅降低目标仓位（控险） |

**计算公式**：
```python
regime_adj = {"bull": 1.1, "bear": 0.85, "extreme_volatility": 0.7, "sideways": 1.0}
delta = adjusted_pct - current_pct
adjusted_pct = current_pct + delta * regime_adj.get(regime, 1.0)
```

#### 修正3：交易成本校验

**规则**：调整幅度 < 1.5%（`V5_COST_THRESHOLD_PCT`）→ 不操作

```python
if abs(adjusted_pct - current_pct) < 0.015:
    cost_rejected = True
    adjusted_pct = current_pct  # 不操作
    action = "hold"
```

#### 修正4：冷却期差异化（2026-06-29 重构）

> **⚠️ 本节为2026-06-29重构后的最新版本，替代原"7天频率限制"设计。**

**设计原因**：C类基金加仓0手续费，但原规则7天内同一基金无论加减仓都锁定 → 加仓被不合理阻塞。

**重构规则**：

| 操作方向 | 冷却期约束 | 说明 |
|---------|-----------|------|
| **加仓**（increase） | **不受7天冷却期约束** | C类基金加仓0手续费，冷却期仅限减仓/赎回 |
| **减仓/赎回**（decrease） | 7天冷却期仍生效 | 减仓有手续费，短期内重复减仓浪费成本 |

**实现逻辑**（position_v5.py `_get_last_execute_date`）：

```python
# 新增 operation_types 过滤参数
last_execute = await _get_last_execute_date(user_id, fund_code, operation_types=["decrease"])
if last_execute:
    days_since = (date.today() - last_execute).days
    if days_since < 7:
        if action_direction == "increase":
            # 加仓不受冷却限制
            frequency_blocked = False
            reason = "加仓不受7天冷却限制"
        else:
            # 减仓/赎回仍受冷却限制
            frequency_blocked = True
            action = "hold"
            reason = "7天内已减仓/赎回"
```

**新增字段**：`frequency_block_direction` — 标记冷却期阻断的操作方向（decrease/None）

### 5.3 操作优先级（完整决策链）

`position_v5.py` 中 `action` 字段的确定优先级（从高到低）：

| 优先级 | 条件 | action | 说明 |
|--------|------|--------|------|
| 1（最高） | 持仓风控闸门触发（`gate_triggered` 非空） | decrease/hold | 见第六节详细规则 |
| 2 | 置信度 ≤ 1星 | hold | 信号太弱，忽略 |
| 3 | 冷却期触发（减仓/赎回方向） | hold | 短期内已减仓/赎回（加仓方向不受冷却限制） |
| 4 | 信号等级 = B（中性） | hold | 无明确方向 |
| 5 | 交易成本阈值未达 | hold | 调整幅度太小，不值得操作 |
| 6（最低） | 以上都不满足 | increase/hold/decrease | 正常矩阵计算结果 |

### 5.4 仓位引擎V5.1升级（2026-06-29）

> **⚠️ 本节为2026-06-29新增章节，记录V5.1四项关键升级。**

#### 5.4.1 分母升级：持仓市值 → 总资产

**旧逻辑**：仓位百分比分母 = 持仓市值（不含现金） → 加仓时目标百分比基于已投入金额计算，不反映真实可用资金

**新逻辑**：分母 = 总资产（持仓市值 + 现金金额） → 仓位百分比更真实地反映资产配置比例

**实现**：
- `position_v5.py` 中 `total_assets = holding_value + cash_amount`
- 仓位百分比 = 持仓市值 / 总资产
- `.env` 新增开关 `V5_POSITION_DENOMINATOR=total_assets`（设 `holding_value` 一键回滚旧逻辑）

#### 5.4.2 组合约束（三层上限）

**旧逻辑**：无组合约束 → 单只基金可占100%仓位 → 7只基金总仓位可达700%

**新逻辑**：三层组合约束上限：

| 约束层级 | 上限 | 说明 |
|---------|------|------|
| 单基金仓位上限 | ≤ 30% | 单只基金不超过总资产的30% |
| 板块仓位上限 | Σ ≤ 25% | 同板块所有基金合计不超过25% |
| 总仓位上限 | Σ ≤ 80% | 所有基金合计不超过80%（留20%现金缓冲） |

**现金感知**：当 `cash_amount / total_assets < 10%` → `cash_warning = True`，文案提示"现金不足10%，建议暂缓加仓"

#### 5.4.3 金额字段（替代假suggested_amount）

**旧逻辑**：`suggested_amount` 用持仓市值 × 百分比差值计算 → 分母不含现金，金额虚高

**新逻辑**：三个独立金额字段：

| 字段 | 计算公式 | 说明 |
|------|---------|------|
| `suggested_target_pct` | 矩阵查表×修正后的目标仓位百分比 | 纯百分比目标 |
| `suggested_buy_amount` | `(target_pct - current_pct) × total_assets` | 建议加仓金额（基于总资产） |
| `suggested_sell_amount` | `(current_pct - target_pct) × total_assets` | 建议减仓金额（基于总资产） |

#### 5.4.4 默认值修正

**旧值**：`current_pct` 默认 0.5（50%） → 新用户/无持仓基金默认半仓，严重偏离实际

**新值**：`current_pct` 默认 0.01（1%） → 接近空仓状态，符合"新基金从零开始建仓"的业务逻辑

## 六、趋势卫士模块详解

### 6.1 核心功能定位

趋势卫士（trend_guard.py）是**后置附加逻辑**，**不修改仓位百分比数值**，只生成趋势解读文案和行为引导建议。

**设计原则**：
- 低侵入：不改动15因子引擎、Sigmoid映射、仓位矩阵
- 可回退：独立开关（`ENABLE_TREND_GUARD=true`），关闭后退回原版V5.0逻辑
- 解耦：与板块情绪系统分时工作

### 6.2 MA20趋势计算规则

**计算逻辑**（trend_guard.py `_calculate_ma20_trend`）：

1. **数据要求**：至少需要20个净值数据点（不足时返回"震荡"，自动静音）
2. **MA20计算**：近20日净值收盘价的简单移动平均
3. **短期趋势**：近5日净值变化率
4. **震荡判断**（三维度，满足2项及以上判定为震荡）：
   - 维度1：区间振幅 ≤ 5%（`(max_price - min_price) / min_price ≤ 0.05`）
   - 维度2：近20日收盘价穿越MA20次数 ≥ 3次
   - 维度3：MA20斜率绝对值 ≤ 0.3%（`(MA20[-1] - MA20[-10]) / MA20[-10] / 10 ≤ 0.003`）
5. **趋势判定**（非震荡时）：
   - `价格 > MA20 且 短期趋势 > 0` → **"上升"**
   - `价格 < MA20 且 短期趋势 < 0` → **"下降"**
   - 其他情况 → 根据价格位置判断（偏向"上升"if `价格 > MA20` else "下降"）

### 6.3 MACD计算规则

**参数**（trend_guard.py 中用于净值序列的MACD）：
- 快线周期 `MACD_FAST = 12`（EMA12）
- 慢线周期 `MACD_SLOW = 26`（EMA26）
- 信号线周期 `MACD_SIGNAL = 9`（EMA9）

> **注意**：这与"情感MACD"（composite_score序列的MACD）的参数不同！情感MACD见6.7节。

**MACD计算步骤**：
1. EMA_fast = EMA(prices, 12)
2. EMA_slow = EMA(prices, 26)
3. MACD线 = EMA_fast - EMA_slow
4. 信号线 = EMA(MACD线, 9)
5. 柱状图 = MACD线 - 信号线

**MACD 6状态信号判定**（2026-06-29 改造，替代原3状态）：

> **⚠️ 原逻辑只检测交叉瞬间（金叉/死叉/中性），~95%时间显示"中性"，改为6状态后覆盖完整MACD周期。**

| 状态 | 触发条件 | 说明 | 配色 |
|------|---------|------|------|
| **金叉** | `DIF[-2] < DEA[-2] 且 DIF[-1] > DEA[-1]` | 交叉瞬间买入信号 | 红色 |
| **多头** | `DIF > DEA 且 非金叉瞬间` | DIF持续高于DEA，多头趋势 | 红色 |
| **多头收敛** | `DIF > DEA 且 DIF连续下降≥2天` | 多头趋势但动能衰减 | amber（橙黄） |
| **死叉** | `DIF[-2] > DEA[-2] 且 DIF[-1] < DEA[-1]` | 交叉瞬间卖出信号 | 绿色 |
| **空头** | `DIF < DEA 且 非死叉瞬间` | DIF持续低于DEA，空头趋势 | 绿色 |
| **空头收敛** | `DIF < DEA 且 DIF连续上升≥2天` | 空头趋势但动能恢复 | teal（青色） |
| **兜底中性** | 数据不足或其他异常 | reason="data_short" 区分"无数据"与正常多空 | 灰色 |

**配色规则**：中国惯例（红涨绿跌），MA20与MACD统一配色方向。

**macd_detail dict结构**：
```python
{
    "signal": str,          # 6状态之一: 金叉/多头/多头收敛/死叉/空头/空头收敛/中性
    "strength": str,        # 强/中/弱
    "trend": str,           # bullish/bearish/neutral
    "days": int,            # 当前状态持续天数
    "last_cross_type": str, # gold/death/None（替代原last_cross字符串）
    "last_cross_days": int, # 上次交叉距今天数
    "histogram": float,     # 当前柱状图值
    "reason": str|None,     # data_short/None（兜底中性专用）
}
```

**关键实现细节**：
- `_count_macd_state_days()` 和 `_find_last_cross()` 需用 `min(len(dif), len(dea))` 做尾部对齐索引，因DIF比DEA长（EMA缩减）
- 震荡市+MACD分支补齐3条文案：多头收敛→"趋势向上但动能减弱"、空头收敛→"趋势向下但有筑底迹象"、中性→"MACD趋势不明"

### 6.4 四象限趋势判定标准

结合MA20趋势方向和MACD柱状图状态，输出趋势判定：

| 价格 vs MA20 | MACD状态 | 趋势判定 | 展示文案 |
|--------------|-----------|---------|---------|
| 高于MA20 | 多头（红柱放大） | 上升 | 📈 趋势健康，建议坚定持有 |
| 高于MA20 | 多头收敛（红柱收窄） | 动能衰减 | 📈 趋势向上但动能减弱，注意风险 |
| 高于MA20 | 金叉（交叉瞬间） | 反弹启动 | 📈 MACD金叉，趋势可能转强 |
| 高于MA20 | 死叉/空头/空头收敛 | 疑似顶部 | 📈 趋势向上，但MACD转弱，建议谨慎加仓 |
| 低于MA20 | 空头（绿柱放大） | 下降 | 📉 趋势走坏，建议减仓 |
| 低于MA20 | 空头收敛（绿柱收窄） | 筑底迹象 | 📉 趋势仍向下但有筑底迹象，暂观察 |
| 低于MA20 | 死叉（交叉瞬间） | 跌势加速 | 📉 MACD死叉，趋势可能加速下行 |
| 低于MA20 | 金叉/多头/多头收敛 | 疑似反弹 | 📉 趋势向下，但MACD金叉，可能出现反弹 |
| 反复穿梭（穿越MA20 ≥ 3次） | 红绿交替 | 震荡 | 📊 震荡市，建议持仓观望，不操作 |

### 6.5 震荡市静音规则

**触发条件**（**双条件同时满足**）：

1. 近20个交易日收盘价穿越MA20次数 ≥ 3次
2. 近20个交易日累计涨跌幅绝对值 ≤ 5%

**静音后行为**：
- `oscillation_silence = True`
- 不输出趋势判定文案
- 不触发持仓风控闸门
- 返回默认响应：`{"trend_signal": "震荡", "macd_signal": "中性", ...}`

**数据不足静音**：
- 净值数据 < 60天 → 自动静音（`oscillation_silence = True`）
- 返回：`{"trend_signal": "震荡", "macd_signal": "中性", ...}`

### 6.6 两套独立闸门体系（2026-06-25 重构）

> **⚠️ 本节为2026-06-25架构重构后的最新版本，替代原"三阶清仓闸门"设计。**

#### 设计原则

Gate体系拆分为**两套独立体系**，各司其职：

| 体系 | 职能 | 触发对象 | 影响范围 |
|------|------|---------|---------|
| **持仓风控层** | 管已有持仓要不要卖 | 已持有的基金 | 调整仓位百分比 |
| **建仓准入层** | 管新资金能不能买 | 新建仓决策 | 准入/排除（不影响已有持仓） |

#### 持仓风控层（Gate1 > Gate2 > Gate-E）

| 闸门 | 触发条件 | 动作 | 说明 |
|------|---------|------|------|
| **Gate 1**（极端回撤清仓） | 60日窗口最大回撤 ≥ 20% | **强制清仓**（adjusted_pct=0.0, action="decrease"） | 无条件止损，contrarian不豁免，~4次/年 |
| **Gate 2**（趋势破位清仓） | MA20趋势下降 **且** 60日回撤 ≥ 10% | **强制清仓**（adjusted_pct=0.0, action="decrease"） | contrarian轨道豁免，~22.5次/年 |
| **Gate-E**（E级提示） | signal_level=E（情绪分>62） | **仅提示不减仓**（adjusted_pct=current_pct, action="hold"） | E级10日+1.97%收益最高，强制减仓踏空 |

**优先级**：Gate 1 > Gate 2 > Gate-E（同一时间仅触发最高优先级闸门）

**关键参数**（`trend_guard.py` 常量）：
- `GATE1_DRAWDOWN_THRESHOLD = 0.20`（极端回撤阈值）
- `GATE2_DRAWDOWN_THRESHOLD = 0.10`（趋势破位回撤阈值）
- `DRAWDOWN_WINDOW = 60`（回撤计算窗口，60个交易日）

**回撤计算**：`_calculate_drawdown(nav_history, window=60)` — 在60日窗口内找最高净值，计算当前净值相对最高点的回撤幅度。

**contrarian豁免规则**：
- Gate 1：**不豁免**（极端回撤无条件清仓，即使逆向投资也不例外）
- Gate 2：**豁免**（contrarian轨道本身就是逆趋势操作，MA20下降是预期内的）

#### 建仓准入层（Gate3）

| 触发条件 | 动作 | 说明 |
|---------|------|------|
| signal_level=E **或** 轨道=excluded **或** 置信度≤1 **或** Gate2已触发 | **准入排除**（admission=forbidden） | 不影响已有持仓，仅阻止新建仓 |

**Gate3与持仓风控层的区别**：
- Gate3 输出 `admission_gate` 字段（forbidden/allowed），不修改 `adjusted_pct`
- 持仓风控层输出 `gate_triggered` 字段，修改 `adjusted_pct` 和 `action`

#### D信号特殊处理（数据驱动）

| 信号 | 轨道 | 评级 | 仓位建议 | 文案 | 回测依据 |
|------|------|------|---------|------|---------|
| D（58-62分） | trend_follow | cautious | **1.0（不减仓）** | "贪婪D信号，注意风险" | D信号10日+0.53%，A股贪婪后动量延续 |
| E（62+分） | — | — | 保持当前仓位 | "极度贪婪，注意风险" | E信号10日+1.97%，强制减仓踏空 |

> **回测结论**：D(58-62)10日+0.53%/胜率52.2%，E(62+)10日+1.97%/胜率61.9%为所有信号最高。策略因D/E减仓跑输基准8.92%。因此D不减仓(pos=1.0)，E仅提示。

#### 实现逻辑（position_v5.py）

```python
# 持仓风控层
gate_triggered = trend_guard_data.get("gate_triggered")
if gate_triggered:
    gate = gate_triggered.get("gate", "")
    if gate == "gate-1":
        adjusted_pct = 0.0; action = "decrease"    # 极端回撤清仓
    elif gate == "gate-2":
        adjusted_pct = 0.0; action = "decrease"    # 趋势破位清仓
    elif gate == "gate-e":
        adjusted_pct = current_pct; action = "hold" # E级仅提示

# 建仓准入层（独立字段，不影响持仓）

# admission_gate = "forbidden" 时仅阻止新建仓，不修改已有持仓
```

#### 闸门适用范围

- **仅对行业/主题基金生效**，宽基基金（broad）**全部豁免**
- 宽基基金判断依据：`fund_category_map.json` 中的 `category` 字段

|------|------|-----------|---------|

| Gate 2 | MA20下降+回撤≥10% | 22.5次/年 | 同上 |
| Gate-E | E级信号 | 仅提示 | E级10日+1.97%收益最高 |

### 6.7 情感MACD（sentiment_macd.py）

**参数**（与净值MACD不同！）：
- 快线 EMA = **5**（对情绪分变化更敏感）
- 慢线 EMA = **20**（平滑中期趋势）
- 信号线 EMA = **9**

**计算标的**：`composite_score`（综合情绪分序列，按时间升序）

**输出**：
```python
{
    "macd_line": float,       # MACD线（快线EMA - 慢线EMA）
    "signal_line": float,     # 信号线（MACD的9日EMA）
    "histogram": float,       # 柱状图（MACD - 信号线）
    "trend": str,             # "bullish" / "bearish" / "neutral"
    "cross": str | None,      # "golden_cross" / "death_cross" / None
    "same_direction_days": int, # MACD与信号同向的连续天数（用于置信度"持续性"评分）
    "momentum": float,        # 动量（MACD变化率）
}
```

**用途**：
1. 置信度"持续性"评分：`same_direction_days / 20 × 100`
2. 信号趋势二阶确认：MACD金叉/死叉辅助判断
3. 防线3辅助：价格-情绪背离时的趋势确认

## 七、板块情绪系统详解（2026-06-25 全量上线 · 2026-07-10 新增三级降级架构）

### 7.1 整体定位

板块情绪系统（sector_scorer.py + recommendations.py + position_rating.py）是面向**申万31个一级行业板块 + 17个中证/国证二级赛道**的独立情绪评估+建仓评级体系，与15因子宽基情绪引擎并行运行。

**与15因子引擎的区别**：

| 对比 | 15因子宽基引擎 | 板块情绪系统 |
|------|--------------|------------|
| 标的 | 4宽基指数（上证/沪深300/深证/创业板） | 31申万一级行业 + 17二级赛道指数 |
| 因子数 | 15因子 | 5因子（IC/IR验证后定稿） |
| 信号边界 | [12,25,38,52,65,80] | [36,40,45,55,58,62]（独立校准） |
| 数据源 | Tushare | AKShare（sw_daily无Tushare权限） + 二期用index_zh_a_hist() |
| 输出 | 情绪分+信号+置信度+MACD | 情绪分+信号+建仓评级+Gate |

### 7.2 5因子方案（IC/IR验证定稿）

| 因子 | 权重 | 方向 | reverse | IC/IR | A股特性 |
|------|------|------|---------|-------|---------|
| TURN（成交额相对强度） | 0.28 | fear | True | \|IR\|=0.30 最强 | A股放量见顶效应 |
| VOL（20日年化波动率） | 0.25 | greed | False | IR=0.28 | A股散户彩票偏好 |
| NHNL（20日新高新低净占比） | 0.20 | greed | False | IR=0.21 | 趋势广度确认 |
| RSI（14日RSI） | 0.15 | greed | False | IR=0.19 | A股趋势延续 |
| DIV（跨板块分歧度） | 0.12 | fear | True | \|IR\|=0.12 | 分歧度惩罚 |

**剔除的因子**（IC/IR验证无效）：
- MOM（60日动量）：IR=0.05，即使缩短到20日仍无效
- ADR（涨跌家数比）：加权版IR=0.04

**A股因子方向反转现象**（重要）：
- VOL/RSI：从 fear → greed（A股散户偏好高波动，波动率高=情绪贪婪）
- TURN：从 greed → fear（A股放量常在顶部，成交额放大=情绪恐惧/见顶信号）

**权重隔离**：`V5_SECTOR_FACTOR_CONFIG` 独立于 `V5_FACTOR_CONFIG`（宽基15因子配置）

### 7.3 三层计算流水线（sector_scorer.py）

```
Layer 1: sigmoid映射 → 5因子各自的percentile→sigmoid_score(0-100)
Layer 2: 加权聚合 → composite_score = Σ(weight × sigmoid_score)
Layer 3: 信号映射 → _map_sector_signal() 独立边界
```

**分歧度惩罚**：`penalty_min=0.85, std_threshold=30`（修复后压缩量0.35pts）

## 十四、每日决策快照系统（2026-06-29 新增）

> **⚠️ 本节为2026-06-29新增章节。**

### 14.1 整体定位

每日决策快照系统（scheduler_snapshot.py）在每日17:05定时记录所有宽基指数/板块/基金的完整决策数据，用于历史回溯、数据分析和CSV本地下载。

**设计原则**：
- 增删基金不影响历史快照：INSERT/upsert模式，永不删除旧记录
- 数据来源与持仓页一致：基金快照直接调用PositionService.get_position_advice()，确保快照数据与用户看到的持仓页数据完全一致

### 14.2 快照数据来源

| 标的类型 | 数据来源 | 说明 |
|---------|---------|------|
| 宽基指数（broad） | `market_sentiment` DB表 | 4宽基指数（上证/沪深300/深证/创业板） |
| 板块（sector） | `sector_sentiment` DB表 | 31申万一级行业板块 |
| 基金（fund） | `PositionService.get_position_advice()` 实时计算 | 确保板块基金使用板块置信度（V5.2双路径） |

### 14.3 定时任务配置

| 配置项 | 值 | 说明 |
|-------|---|------|
| 触发时间 | 17:05 | 因子16:00 + 净值17:00 之后 |
| 调度器 | APScheduler | scheduler_snapshot.py |
| 模块 | scheduler_snapshot.py | 3部分：宽基→板块→基金 |

### 14.4 API接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 快照历史查询 | GET | `/api/v5/snapshot-history` | 按日期/类型/信号/操作筛选 |
| 快照统计汇总 | GET | `/api/v5/snapshot-stats` | 统计汇总 |
| 快照CSV下载 | GET | `/api/v5/snapshot-download` | UTF-8+BOM CSV，RFC 5987中文文件名 |
| 手动触发快照 | POST | `/api/v5/snapshot-trigger` | 手动触发当日快照生成 |

### 14.5 CSV下载技术细节

- **编码**：UTF-8 + BOM前缀(`\xef\xbb\xbf`)，确保Excel/WPS正确打开中文
- **文件名**：RFC 5987双编码 — ASCII `filename=snapshot_...csv` + UTF-8 `filename*=UTF-8''决策快照...csv`
- **中文枚举映射**：5个字段输出中文而非英文枚举值

| 字段 | 英文→中文映射 |
|------|-------------|
| target_type | broad→宽基指数 / sector→板块 / fund→基金 |
| track_type | contrarian→逆向轨道 / trend_follow→趋势轨道 / excluded→排除轨道 |
| position_rating | watch→观望 / buy→可建仓 / strong_buy→强力建仓 |
| action_advice | increase→加仓 / hold→持有 / decrease→减仓 / sell→清仓 |
| overall_status | normal→正常 / warning→预警 / stop_loss→止损 |

### 14.6 前端组件

**SnapshotDownloadButton.tsx**：日期范围选择器 + 类型选择（宽基/板块/基金/全部）→ 浏览器直接下载CSV

## 十八、盘中预演模块详解（2026-07-03 新增 · 2026-07-06 增强T16-T24）

### 18.1 核心定位

盘中预演模块是**实时盘中信号模拟系统**，在交易时段（9:30-15:00）基于实时基金估值(gszzl) × 弹性系数，推演当前情绪分可能的变化方向和幅度，为投资者提供盘中决策参考。

**设计原则**：
- 低侵入：不修改15因子引擎、Sigmoid映射、仓位矩阵，仅在已有信号基础上叠加预演偏移
- 可回退：独立开关（`ENABLE_INTRADAY_PREVIEW=true`），关闭后持仓页回到纯信号展示
- 实时性：交易时段5分钟刷新一次，非交易时段显示"非交易时间"提示
- 安全性：预演分数偏移受 `SCORE_DELTA_CLAMP=20` 限制，不会产生跨信号等级的剧烈跳变

**一句话逻辑**：
实时估值涨幅(gszzl) × 弹性系数(板块波动率自适应) → 预演分数偏移 → 昨日分数 + 偏移 → 预演分数 → 操作建议 + Gate区间

### 18.2 弹性系数计算（scheduler.py `_calculate_elasticity`）

弹性系数是预演模块的核心参数，表示"估值变化1%对应情绪分变化多少点"。

**计算公式**：
```
弹性系数 = 基础系数(2.0) × 板块波动率分级修正 × 行情极端状态降敏
```

**板块波动率分级（`_get_volatility_grade`）**：

| 分级 | 适用板块 | 系数范围 | 说明 |
|------|---------|---------|------|
| 高波动 | 半导体/电子/国防/计算机/通信 | 1.5 ~ 2.0 | 高波动板块估值变化对情绪影响大 |
| 中波动 | 大部分申万一级板块 | 2.0 ~ 2.5 | 标准弹性范围 |
| 低波动 | 银行/公用事业/交通运输/煤炭/钢铁 | 2.5 ~ 3.0 | 低波动板块需要更大估值变化才触发信号切换 |
| 无板块 | 宽基基金 | 2.0(默认) | 无板块归属时使用基础系数 |

**极端行情降敏**：
- |gszzl| > 5%：弹性系数强制降至1.0（极端行情下估值波动不可靠，降敏防止信号跳变）
- |gszzl| > 3% 且 < 5%：系数在低范围(1.5~2.0)
- |gszzl| < 1%：系数在高范围(2.5~3.0)

**弹性系数周更新**（`_run_intraday_elastic_weekly`）：
- 每周五 15:45 基于过去20个交易日的实际 vs 预演偏差重新计算弹性系数
- 更新后的系数存入 Redis，供下一周预演计算使用

### 18.3 预演分数计算流程

```
1. 获取实时估值(gszzl) — eastmoney.py 双路冗余
   ↓
2. 计算弹性系数 — _calculate_elasticity(板块波动率×行情状态)
   ↓
3. score_delta = gszzl × 弹性系数 × 100
   score_delta = clamp(score_delta, ±20)  ← 防信号跳变
   ↓
4. preview_score = yesterday_score + score_delta
   preview_score = clamp(preview_score, 0, 100)
   ↓
5. 信号映射：_score_to_signal(preview_score, V5边界)
   ↓
6. 操作建议：_gate_price_to_position(闸门触发价→进度条位置)
   ↓
7. 构建 threshold_data（前端ThresholdBar需要的区间数据）
   ↓
8. 写入Redis：intraday_preview:v1:{date}:{fund_code}:{user_id}
   TTL=300s(5min刷新)
```

### 18.4 双路估值冗余（eastmoney.py `get_fund_realtime_nav`）

| 路径 | API | 优点 | 缺点 |
|------|-----|------|------|
| **主路径** | fundgz HTTPS JSONP | 响应快、格式简单 | 依赖东方财富接口 |
| **备路径** | FundMNFInfo Mobile HTTPS JSON | 数据完整(含NAV+gszzl) | 响应稍慢 |

**异常阈值**：|gszzl| > 10% 视为异常数据直接丢弃（避免非交易时段或基金暂停时返回的错误估值）

**缓存策略**：
- 成功请求：TTL=300s（与scheduler 5min刷新对齐）
- 失败请求：TTL=60s（快速重试）

### 18.7 信心等级与信号变化方向

**信心等级**（`_get_confidence_note`）：

| 等级 | 标签 | 含义 | 触发条件 |
|------|------|------|---------|
| 1 | 早盘波动大 | 估值变化可能剧烈，预演偏移不太可靠 | 9:30-10:30 |
| 2 | 午盘参考 | 估值相对稳定，预演较可靠 | 10:30-14:00 |
| 3 | 尾盘趋稳 | 接近收盘，估值接近结算价 | 14:00-15:00 |

**信号变化方向**（`_calc_signal_change`）：

| 方向 | 含义 | 触发条件 |
|------|------|---------|
| upgrade | 信号可能升级（如B→A） | preview_signal > yesterday_signal |
| downgrade | 信号可能降级（如A→B） | preview_signal < yesterday_signal |
| stable | 信号维持不变 | preview_signal = yesterday_signal |
| jump | 跨级跳变（如B→S+） | 跨≥2个等级 |

### 18.8 对账校准系统（`_run_intraday_preview_reconciliation`）

**核心逻辑**：每个交易日收盘后，比较当日所有预演分数 vs 实际结算分数，计算偏差。

**校准策略**：
- 偏差 > `INTRADAY_PREVIEW_SCORE_DELTA_CLAMP=20` → 弹性系数下调10%
- 偏差 < 5 → 弹性系数上调5%（预演偏差小说明弹性合适）
- 连续3日偏差 > 15 → 弹性系数下调20%（系统性偏差需大幅修正）

**`_signal_level_distance`**：计算两个信号等级之间的级数距离（用于判断是否跨级跳变）

## 二十一、MACD双系统与背离检测详解（2026-07-13 新增）

### 21.1 核心定位

MACD双系统是V5.4的核心升级：在原有SentimentMACD(情绪分数MACD)基础上，新增PriceMACD(价格MACD)，两套MACD并行计算，通过背离检测发现"价格与情绪方向不一致"的信号。

**一句话逻辑**：
SentimentMACD(5/20/9) + PriceMACD(12/26/9) → detect_macd_divergence → DIVERGENCE因子(第15因子) → 情绪分数微调

### 21.2 双系统参数对比

| 系统 | 文件 | 快线 | 慢线 | 信号线 | 数据源 | 输出 |
|------|------|------|------|--------|--------|------|
| SentimentMACD | `app/engine/sentiment_macd.py` | 5日 | 20日 | 9日 | 综合情绪分数历史 | DIF/DEA/HIST/trend/cross/momentum/same_direction_days |
| PriceMACD | `app/engine/price_macd.py` | 12日 | 26日 | 9日 | 收盘价历史 | 同上（格式一致） |

**EMA实现**：SMA初始化 + 乘数 `2/(period+1)`，尾部对齐（2026-07-13 P2修复，原头部对齐导致DIF时间错位14天）

### 21.3 背离检测算法

**文件**：`app/engine/divergence_detector.py` → `detect_macd_divergence()`

**检测逻辑**：

| 背离类型 | 条件 | 信号 | 含义 |
|---------|------|------|------|
| 顶背离(top) | PriceMACD hist↑ + SentimentMACD hist↓ | sell | 价格涨但情绪弱 → 上涨动力衰竭 |
| 底背离(bottom) | PriceMACD hist↓ + SentimentMACD hist↑ | buy | 价格跌但情绪强 → 下跌动力衰竭 |
| 无背离(none) | 趋势同向 | None | — |
| 数据不足(insufficient_data) | min_len < 60 | None | 需≥60条历史（当前43条，约2月后激活） |

**参数**：
- window=20（回看20天）
- 趋势判断：线性回归斜率 + std-based阈值
- confidence：≥120天=high, 60-119天=low, <60天=insufficient_data

### 21.4 DIVERGENCE因子

**文件**：`app/engine/factor_engine/divergence.py`

**raw_value映射**（direction=fear）：

| 背离类型 | raw_value | Sigmoid后 | 反转后(100-score) | 含义 |
|---------|-----------|----------|-------------------|------|
| 顶背离(top) | 50 + strength×50 (50-100) | 高分 | 低分 | 恐惧（市场仍贪婪但即将反转） |
| 底背离(bottom) | 50 - strength×50 (0-50) | 低分 | 高分 | 贪婪（市场仍恐惧但即将反转） |
| none/insufficient | 50 | 中性 | 中性 | 无影响 |

**激活条件**：sentiment MACD history ≥ 60条（当前43条，约2个月后自动激活）
**未激活时**：所有基金返回50.0（中性），对情绪分无影响
**优雅降级**：任何异常返回50.0，不阻断pipeline

### 21.5 前端展示

**MiniMacdChart**（`SignalBoard.tsx`内联）：
